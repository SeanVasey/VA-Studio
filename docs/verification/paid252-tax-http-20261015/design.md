## Coherent boundary

Compose retained Tax255 checkout and Paid252 typed Tax grant/delivery domains into separately typed HTTP endpoints, conditionally mounted by exact boolean flags. No live adapter/merchant configuration is supplied. Frozen render profiles/members, V1 domains/controllers, original Tax producer/consumer receipts/commit bodies, original five-table schema and new delivery schema stay unchanged. Ordinary shared V1/Identity descriptorP2 and membership afterCommitP2 remain frozen. No frontend Tax page/history-index discovery is invented; these identifier-only endpoints serve the retained original purchase and actual private bytes. A future Tax screen/index must use its own reviewed source/current-owner closure.

Use new PaidTaxController, PaidTaxPrivacy, PaidTaxJson, PaidTaxForm and a thin PaidTaxReads::show seam. Show invokes actual PaidTaxCommands::run and PaidTaxGrants::project under its original source/consumer/projection receipt; it never constructs entitlement from copied rows or V1 types. Use ProductionCustomerSessions::principal(request) and actual customer guard User, after literal PaidTaxPolicy capture; no request credential/owner/price/provider/proof field confers authority.

## Bounded parsing and response lifecycle

Early private intake rejects query strings, body onGET, wrong methods/overrides, Range/If-Range, cross-site or wrong Origin, nonidentity encoding, noncanonical content types and overlarge declared/actual bodies. JSON max64KiB/depth16 requires an object and decoded duplicate/escaped-key refusal; domain exactkeys reject extras/nested/wrong types. Native redemption form max4KiB requires exactly token+_token, validates decoded key aliases/duplicates and token43/CSRF40 syntax before replacing the CSRF request bag; token-only domain body is separately cached. Other POST endpoints accept only canonical JSON. New codec types use Tax exceptions, with no V1 authority or serializer rebranding.

Every successful private JSON projection is encoded/bounded before returning a streamed response. The callback invokes the original PaidTaxProjectionRead::proveBeforeBytes immediately before primitive echo, after encoding/response construction. No resolver/config/logging/response negotiation occurs between proof and positive bytes. A late refusal emits only a fixed error object with its actual bounded status; it never emits the original projection/token. Status headers may already be200 on a streamed late refusal; tests distinguish wire header from private error body. Encoding/response-construction failure and never-started disposal must abandon the original read, including after policy/budget withdrawal, without minting replacement proofs or touching unrelated frames. A new small owned JSON response wrapper may own this cleanup if destructor/explicit-close behavior requires it; tests use actual root response disposal and demonstrate fresh same-owner command after release.

The earliest globally prepended mounted Tax root seam captures PaidTaxRequestBudget from the server REQUEST_TIME_FLOAT immediately after callback-free literal flag/environment admission, before raw body intake, identity, route/controller resolution or response callbacks. A private server-held WeakMap keyed by the exact Request instance owns that original budget and a one-use controller-claim state; its value must not hold a strong reference to its Request key. No mutable request attribute may carry or replace the authority-bearing budget. Repeat capture, absent context, wrong request, replacement and second claim refuse; no fallback recapture. Budget creation is skipped entirely on default-off/unmounted refusal. Existing capture owns its exact receivedAt and original live min-only allowance. The controller obtains only the original privately held instance, proves its initial deadline immediately after identity, and passes budget.receivedAt and budget to actual PaidTaxDownloads::redeem(batch,authorization,token,...). Real preparation happens outside transactions; second authenticated commit records only one technical attempt. Return actual PaidTaxTransfer metadata, with original descriptor and before-first-nonempty-byte closure. Stream callback only echo of bytes through transfer::writeTo; on refusal it logs only exception class where necessary and emits no appended JSON/error bytes into the attachment. Headers/filename/content hash/length come only from the typed transfer, never request input. Response-construction/callback failure or never-started response disposal closes transfer/read/lease idempotently, retaining a durable spent attempt. No HTTP callback may renew budget, authorization, snapshot or transfer clocks.

The existing admission contract remains valid-to-start plus current-first-byte, not perpetual reauthorization or a host send-timeout guarantee. Existing SourceV2 and owner raw closure handle late withdrawal; before-bytes callback order remains in the domain. No new filesystem read/hash/copy/DB/proof shortcut belongs in the controller. Default snapshot300/transfer limits and renderer/profile source stay unchanged.

## Required corrected design mechanics

The original independent REVISE record is retained. These four corrections govern implementation, rather than being optional cleanup suggestions.

1. **Early original request budget.** Root captures and privately enrolls the original budget before any callback-producing body/identity/controller work. A concrete private WeakMap context can record one exact-request budget and one controller claim without holding its key strongly or using caller-mutable attributes. New calls cannot replace/renew it. Tests mutate request attributes/server start fields and introduce delayed body/resolver/identity work after capture, then verify original expiry/allowance and no attempt on exhausted admission. Default-off paths prove no budget/snapshot policy/identity resolution or SQL. A finished request cannot re-enroll an already admitted context while the same Request is alive.
2. **Mandatory response lifetime ownership.** A small plain original-owner object is allocated before callback-producing domain/encoding/response-factory/protect work can leave a captured projection unmanaged. It stores only original read or transfer handles and provides idempotent explicit close/destructor. An owned streamed response receives that holder and closes it on constructor/factory/encoding/protect/callback exception, explicit disposal and never-started destruction. Transfer ownership is established immediately upon return and before response construction; original projection holder exists before the domain operation captures its read. The callback captures the plain owner/encoded payload, never the response itself; neither owner nor context holds a response/self-capturing cycle. Failure preserves the original exception, durable attempts and unrelated/reopened/replacement frames. Cleanup uses captured handles even after flag/policy/budget withdrawal. Tests force each allocation/encoding/factory/protect gap, duplicate callback, never-started disposal and fresh command after cleanup. Lifecycle tests must unset actual responses and inspect original observer/lease release, not merely call a helper in isolation.
3. **Private errors independent of Accept.** Both prefixes force JSON/no redirects in root shouldRenderJsonWhen, even Accept:text/html, before route/controller/private middleware. Root dontFlash excludes token/nonce/requestKey/proof/declarations and existing credentials; validation/session failure must never flash a private body. Fixed reporter uses exception class only; it cannot fall through to framework request/trace logging. Root response sanitizes pre-privacy422/419/500/503 as well as404/405/429, always private/no-store/nosniff/noindex/no-referrer/Cookie Vary. Any propagated Allow/Retry-After/rate metadata comes from a small explicit allowlist, bounded scalar lengths and validated shapes; arbitrary original headers are discarded. Test genuine validation/session exceptions ahead of privacy with hostile Accept and private markers, asserting no redirect/history/flash/log disclosure.
4. **Cached routes and once-only producer intake.** Build-time mount/provider guards use exacttrue plus local/testing and flags shipfalse. Document route:cache/config-cache rebuild as a deployment requirement without claiming any host change. Per-request root guard independently refuses false/nonboolean mount or non-rehearsal environment even with a stale previously mounted route table. Consumer/producers stay separate. Producer root delegates exactly once to existing intake, preserving its16KiB/depth8 and deliberate controller two-pass JSON duplicate scan; it must not re-read the same raw input resource through duplicate middleware. Update manual producer fixture mounting to set the explicit flag and avoid adding a second root intake; default no binding/query/identity remains. Prove stale route tables, environment withdrawal/nonboolean flags, default unbound transport, once-only actual raw stream and affected producer bodies.

CSRF evidence must explicitly disable Laravel's ordinary runningUnitTests bypass and exercise actual token equality/mismatch/rotation with genuine web sessions for JSON and native redemption forms. A test-client419 without the actual comparison is insufficient. Session blocking/throttle/cache fixtures must be declared synthetic; no distributed-cache, host or browser-FPM claim follows from local requests. Root producer/consumer registration alone does not activate either commerce policy or supply merchant inputs. All other original proposal limits and review/check/merge gates remain.
