## Request replay and historical access

Requests are closed lists of one to ten unique tracks with exactly four positive, JavaScript-safe integer IDs per line, sorted by track identity. Numeric strings, floats, extra totals and duplicate tracks refuse. Prices remain positive USD minor-unit integers bounded by existing offer limits; checked integer accumulation refuses overflow. Each selected graph table is bounded to 256 rows, each track/offer/user audit history to 256 rows, catalog canonical evidence to 393,216 bytes, retained plaintext to 524,288 bytes and ciphertext to 1,048,576 bytes. Exceeding a bound refuses; it does not truncate a selector or silently widen scope.

An unused creator/key requires a signed confirmation of exact actor authority, capability/context projection and catalog baseline. Source/actor/catalog drift before apply refuses without packet/audit writes. Exact authenticated saved requests replay the retained model without new writes, even after source successors, closure, catalog movement or license expiry. A changed request on a used creator/key refuses. Lost responses recover through the creator key, using current staff/MFA authorization and authenticated historical source/candidate/approval/cipher/line/audit commitments. Historical access never reinstates capability or catalog sale eligibility. Fresh confirmation on a used key refuses; use recovery or replay the original confirmation. Recovery is bounded and standalone; it cannot inherit an outer transaction's old read view.
