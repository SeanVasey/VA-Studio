## Concrete configured transport

`Notifications\SmtpIdentitySettings::production(host, port, security, sender, hello, username, password, revision)` validates a server-owned FQDN endpoint, sender/EHLO identity, required AUTH LOGIN credentials and opaque configuration UUID. The only security choices are `implicit_tls` and `starttls`; cleartext, IP/loopback production endpoints, control-character/header injection and missing credentials are refused. The fixed Symfony SMTP client requires TLS, verifies peer certificates and hostname, disallows self-signed peers and uses TLS 1.2/1.3 with bounded connection timeouts. There are no application SMTP listeners, loggers or custom authenticators.

`ConfiguredSmtpIdentityTransport` implements the existing typed `IdentityNoticeTransport` contract. Each instance permits one claim and must be bound transiently. Its capability is `configured-smtp-identity-v1:` plus an immutable commitment to endpoint, TLS, sender, configuration revision, keyed account/credential commitments and trust-root hash. Changing those settings changes the terminal capability. Credentials and the private proof are never a public configuration projection, serialized object or retained error diagnostic. Server setup happens before worker terminal proof; submit uses captured scope/environment facts and fixed internal MIME/SMTP behavior.

The actual sink tests execute both implicit TLS and STARTTLS, AUTH LOGIN and SMTP DATA through the real notice worker, then use the proof received in that message to complete and authenticate an actual new synthetic account. SMTP acceptance alone creates neither a user nor an origin. The loopback factory uses literal `127.0.0.1`, synthetic `.test` addresses/credentials and an ephemeral certificate/private key outside Git. It is available only in local/testing. Production settings constructed in testing cannot connect externally even with a production-shaped mail object.

Failure before DATA is retained as definitely-not-submitted only when the client positively knows DATA was not admitted. Once SMTP 354 permits DATA, every later error or lost final acknowledgement is unknown and is not automatically resent. A positive 250 is submission acceptance, not mailbox delivery or account verification. Actual tests retain the existing outbox classification for RCPT rejection, missing TLS/AUTH, untrusted certificate and lost acknowledgement; private Symfony diagnostics do not escape.

## Callback-free proof after normal commit

Normal source writes, audit and framework commit events must finish first. A postcommit proof failure means those writes remain durable and the response is honestly unknown; it is not a rollback or permission to reset a retry. No identity or source write is performed by this API.

`IdentityCommittedFrame::begin(CurrentRows, originalMonotonicDeadlineNs)` creates one sealed read-only raw PDO transaction at framework depth zero on the captured current writer/schema. It refuses an existing primary or secondary transaction. SQLite query_only is enforced and restored; native next-transaction READ COMMITTED and READ ONLY preserve the captured session defaults. One random SAVEPOINT is explicitly authorized solely as the physical sentinel, not nested Laravel/business work. A direct commit/reopen loses it, even if PDO still reports an active transaction. The original caller deadline is immutable; this API cannot renew it or mint a new principal.

Committed identity reads are permanent qualified nonlocking SELECTs, with the same physical schema admission. They deliberately omit FOR UPDATE because the validation transaction is read-only. Consumer module readers must also use fixed bounded nonlocking SQL; `frame->reader()` exposes the existing captured PDO/driver getter seam, not permission to invoke CurrentRows' ordinary MySQL locking queries.

The committed API is explicit:

1. Capture the monotonic operation deadline once before the original normal transaction; retain its raw identity evidence and build the private DTO through normal domain work.
2. After Laravel commit/events, begin the frame and call `lockCommitted(identity, frame, originalRaw)` before module validation reads. It compares the original identity evidence and grants no renewed authority.
3. Prove retained feature bindings with `verifyOriginalBindingCommitted` / `proveOriginalBindingCommitted`, and prove the module's current permanent raw graph against its original evidence.
4. Call `proveCommitted(identity, frame, originalRaw)` last. It rechecks feature/current identity, closes mutable user/account bytes after deep history/floor work, consumes the physical sentinel and commits only the read-only validation frame internally. No framework commit event or extensible gap follows that final identity fence.
5. Return only the prebuilt DTO; always `frame->close()` in finally. Cleanup refuses to roll back a replacement/foreign transaction whose sentinel is absent. Such a frame failure releases no private response or automatic retry; original source writes stay retained.

The lower-level ProductionCustomerAccess committed methods supply current or original signed observation proof to the sealed frame without changing the old methods. No source insert/execute API is exposed by the frame or committed reader. Tests issue actual raw source UPDATEs and confirm database-enforced refusal, then confirm normal writable behavior is restored after closure.
