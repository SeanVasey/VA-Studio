## Independent design correction — mixed history coverage (P2)

The initial proposal above was insufficient: v1 normalization silently omitted missing-original declarations, so checking only known original identities against a newest complete v2 snapshot cannot recover declarations omitted from older v1 source packages. A v2 re-export that omits such a declaration cannot establish historical completeness.

**Selected initial rule:** any retained `legacy_history_batches` row with the same exact `source_system` and transform `vasey-legacy-history-transform-v1` blocks new verified-grant reviews and classification with `declaration_history_coverage_unproven`. Check every retained batch, including incomplete batches and batches older than the newest v2. Unknown transform versions also refuse admission. This rule is applied in read-only inspection/classification and again in the authorized write transaction. It supplements newest-v2 completeness; it does not replace integrity/current-version/provenance checks. No classification or historical review row is mutated, and old source packages, originals and records remain retained exactly.

V1-only and mixed histories remain archive/read/reconciliation/resume capable under their existing version contracts. Importing v2 snapshots into a mixed history never removes this eligibility blocker. Changing a source-system identifier, deleting old batches or generating equivalent records is not an upgrade or escape path and must not be recommended as recovery. Production historical activation remains unavailable for those histories.

There is **no approved immutable package-coverage mechanism in G1b**. Any future recovery design must independently bind every relevant original v1 source package to genuine re-normalized/imported v2 evidence with immutable provenance and explicit completeness; that is separate reviewed work. The current proposal therefore introduces no guessed origin-package identity, creator/segment coverage attestation or fabricated completeness marker. The previously proposed mapping of known v1 originals to current declarations is insufficient to lift this source-wide blocker.

Required regressions: v1 A containing an omitted missing-original declaration → complete v2 B omitting it remains refused; known v1 originals all mapped into v2 still refuses; incomplete v1 batch also refuses; v2-only history may satisfy declaration gates if all other evidence is valid; classification of an existing review withdraws without modifying its row when relevant v1 history is present. No DB or G1b implementation is authorized by this design correction. Await final independent design findings and rereview approval.

Discover declaration identities from **every retained version ever associated with the selected line**, retain every candidate key, and resolve each to its exact latest advertised version without discarding moved-away versions. A second declaration cannot clear `multiple_contracts` by moving to another line/order; omission cannot clear it either. A later exact relink back does not establish authorization for the intervening identity movement: any retained declaration version showing multiple line/order associations for the candidate key is an unresolved relink blocker. This intentionally conservative rule requires no guessed commercial semantics.

Apply historical-association/relink refusal in inspection/classification and again in the authorized write transaction, independently of delta category, dispositions or the V3 operator procedure.
