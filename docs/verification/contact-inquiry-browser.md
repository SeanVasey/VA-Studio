# Real inquiry browser verification

`tests/browser/contact-inquiry-persistence.spec.ts` exercises the actual built customer page and actual Laravel/Filament backend. It does not intercept routes, replace transport, seed a saved inquiry, or invoke Livewire test components. Both configured projects submit the form using its real CSRF token, verify one exact encrypted persisted payload and receipt, replay the same real HTTP body without duplicating records or audits, and use a separate browser context to sign in through the ordinary staff login. The staff journey opens the inbox and detail, confirms read and archive actions, checks visible state without a reload, and confirms the archived record leaves the default new inbox. A private contact preview has no inquiry form.

The CLI-only fixture helper refuses execution without the wrapper's pinned loopback origin, local environment, real temporary directory under the operating system's temporary root, nonempty SQLite database, uncached isolated configuration, existing bootstrap fixture identities, and a fresh random marker written exclusively by the wrapper. It verifies fresh staff Gate/MFA authority for every operation and accepts only exact argument counts. The notice, internal reference, verified operator and enabled flag are fixed synthetic values. The helper creates and publishes synthetic contact content through the normal site domain, retains metadata exclusively with private file permissions in the same database transaction, and rolls publication back if that metadata cannot be written. It retains the previous publication and restores it in a nested `finally` even if creating or closing the staff context fails. Restoring a previously unpublished site activates its exact retained baseline through normal rollback; immutable publication history is preserved. The helper refuses to overwrite an unrelated intervening publication.

Database verification compares exact decrypted Unicode/newline/script-text input, hash and notice snapshots, retained release hash, state/version and staff audit identity. It also checks raw storage for plaintext leakage, received/read/archive audit counts, a fresh staff inbox audit and absence of commerce record changes. The browser checks each state-changing Livewire response and reloads the archived detail to confirm retention. Credentials, real customer data and production setup never enter this fixture. Screenshot artifacts contain clearly synthetic details.
