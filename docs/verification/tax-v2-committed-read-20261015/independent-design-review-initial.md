## Required corrections

1. **Keep the abort anchor older than every cycling held anchor.** Design lines7/14/16 do not specify marker order. HeldSourceTransaction::capture creates its marker at lines34–42 and prove releases/recreates it at lines47–53. On SQLite releasing an older savepoint removes younger savepoints. An abort marker created beside/after the held marker can therefore disappear during ordinary source proof, defeating cleanup. Establish the unpredictable original abort witness before HeldSourceTransaction creates its marker, after exact native/default-statement PDO and original top-level ownership are admitted, and prove it survives repeated source fences. Never release/recreate that older marker as an authority-renewal shortcut during normal source proof. Abort may release the positively present original marker then roll back the entire still-owned physical transaction; it does not ROLLBACK TO a marker and continue. Receipt-disabled births may avoid this extra capability, but a flag enabled later cannot obtain one.

2. **Clean only original framework callback records as well as physical PDO state.** ManagesTransactions::handleCommitTransactionException lines232–250 can lower depth1 to0 without PDO rollback or manager rollback. A captured-PDO rollback alone leaves the original manager's pending afterCommit record available to a later unrelated commit. Capture the original native connection, manager, name and record object ownership while held. Cleanup must remain independent of expired deadline, withdrawn Tax/identity/consumer policy, replaced aliases/instances/primary or observer invalidation. It must not resolve a manager/primary or clear all records merely because current depth is0: an unrelated reopened frame can have records on the same connection. Discard only positively owned original records/descendants; preserve peer/reopened records and callback ownership. If rollback callbacks are invoked, specify their ordering/exception handling so they cannot prevent original-record discard or replace the original error. Restore the observer only if the captured connection still owns that exact observer. Both sibling cleanup calls must be idempotent. Retain a cleanup handle in the owner before DB::transaction returns; an exception during commit prevents returning the closure result.

3. **State the afterCommit-throws outcome without a false positive witness.** ManagesTransactions::transaction lines66–72 invokes the manager before TransactionCommitted. The manager executes managed afterCommit callbacks at line94. A callback can throw after physical commit and before the observer sees its matching committed event. Receipt phase must remain unobserved/invalid and prepared output must be suppressed; neither idle PDO nor absent abort marker proves the positive original commit. Error cleanup must conditionally restore/invalidate, leave already committed effects and unrelated reopened work untouched, and never retry/compensate or claim rollback. This does not solve the adjacent ordinary membership afterCommit P2. Successful managed afterCommit callbacks and ordinary committed delegates must both precede closed configuration/raw/history checks and positive-witness observation.

4. **Require autocommit before every closed MySQL table/identity read.** Design lines13/20 promise no new transaction. Depth0 plus !PDO::inTransaction is insufficient if a callback set session autocommit=0: the first ordinary InnoDB table SELECT can begin an implicit transaction. The Tax context must establish @@session.autocommit===1 before all plain source and identity/schema reads after commit, and bracket reads with exact captured-primary/depth/driver/default-statement/context checks. Refuse without switching autocommit back or opening a new transaction; preserve callback-owned session state. Generic context and CurrentRows::committedReadOnly do not themselves establish this. Use fixed qualified nonlocking SELECTs; “no locks” should mean no explicit row locking or transaction, not absence of internal metadata locks or an arbitrary-SQL wall-clock guarantee.

5. **A caught receipt refusal must not disarm the original commit fence.** Define behavior when a third/incompatible mint, serialization attempt or proveClosed called while held is caught inside the transaction. Restoring the ordinary dispatcher after invalidation can allow a later physical commit to bypass an already registered optional consumer admission. Preserve the valid installed observer on harmless rejected mint, or retain a poisoned observer that refuses commit until positively owned abort; never silently remove an active original source/admission fence. Specify whether third refusal preserves siblings. A failed closed proof is consumed; no receipt, seal, raw/context capability or observer clone/serialization can reset that state. Handle mint failures after observer installation even if no new receipt is returned.

6. **Make birth identity, original budget and observer exclusion explicit.** Capture the earliest Tax source-birth monotonic sample before policy/decryption/callback work; cap once by min(caller original deadline, original generic context bound, original Tax birth+300s). Subsequent mint/proof only shortens/compares this original bound, with no policy or clock-age recapture. Siblings must share the exact source object, original reader object, birth context, deadline and optional capsule identity; a substitute reader on the same PDO is not a new original reader. Capture literal full Tax policy and birth receipt flag before callbacks, require true/exact V2 version for mint only, and reject late enable/replaced configuration. Disabled receipt keys must not incidentally prohibit existing nonreceipt SourceV2 reads. Tax must not call generic requireReceiptsEnabled or borrow the V1 flag's purpose.

   Tax installation can eagerly reject existing V1/NEW-command observers. The frozen OriginalCommitDispatcher factory only rejects its own type and CheckoutCommandCommitDispatcher; frozen NEW-command factory only recognizes its own/V1 type. They cannot eagerly recognize a future Tax observer without a forbidden shared edit. The contract must therefore distinguish reverse installation: Tax detects that its connection dispatcher was replaced/wrapped and refuses before physical commit, while preserving replacement ownership, rather than claiming symmetric eager installation refusal. Tests must cover both directions and both ordinary DB::transaction and disallowed nested/reentrant flows. A later source/frame/observer can never satisfy the old receipt.

## Raw and callback sequencing contract

Use a new Tax-only helper whose private server factory derives its facts from authenticated SourceV2. No caller-provided expected arrays, SQL or receipt token may grant authority. Explicitly enumerate the bounded singleton/duplicate-detection selectors: all four public IDs; exact order tuple; request by order/idempotency; binding by request/provider session; reviewed by request/order/binding/provider session/provider payment. Use deterministic limits with a second-row sentinel and compare the authenticated original set, not merely the first returned row. Capture global predicates with qualified current FOR UPDATE on MySQL before sealing; repeat current reads with min(original,5s) row wait and finally restoration. Apply the prior actual-isolation/canonical uniqueness conditions, not an RR snapshot or session-default inference.

Historical owner_key/account relation, origin and original verification/challenge prefix belong to the existing identity receipt; current password/access changes may not revoke legitimate historical paid evidence. Authentication/decryption/normal services and identity sealing happen before the final Tax config/permanent/raw/identity/anchor fence. After that fence use only captured native metadata/raw comparisons and original witness preparation, with no ProductionTaxPaidOrderSourceV2::proveRetainedCurrent re-entry that decrypts or resolves authority. Closed proof compares original bytes and identity seal on the captured primary; it cannot remint/adopt source/reader/frame/admission. Validate permanent physical identity/definitions under declared healthy canonical schema conditions, exclude allocator-only counters where justified, and keep full damaged restore/external DDL/trigger acceptance open.
