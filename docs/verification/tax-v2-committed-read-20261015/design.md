## Contract proposed for independent review

SourceV2 remains the sole authenticated source of exact retained order/request/binding/reviewed-payment and original historical buyer facts. Its Tax birth context takes the earliest hrtime sample and reads the literal Tax configuration/receipt flag from the captured standard repository before policy/decryption/other callback services. When receipt-enabled, it admits the captured internal/default-statement primary, original top-level connection and original transaction-manager record, then creates an unpredictable abort anchor BEFORE HeldSourceTransaction creates its younger cycling anchor. Only afterward can callback-capable policy/source work run. Capture closes those original objects and values again afterward; it cannot adopt a changed flag, container, manager or primary. Receipt-disabled birth may omit cleanup capability and still support existing nonreceipt SourceV2 reads. It returns unchanged v2 line bytes. Adding closed-original observation never permits accepting that source outside its held frame or reusing it in a new transaction.

The connection-local observer is Tax-specific and concretely typed to V2. It delegates normal events first, closes the optional current consumer admission, authenticates/seals historical identity, then performs callback-free final captured configuration/permanent/raw source/anchor proof. Only afterward is the original identity-owned positive-commit witness prepared. Matching committed event follows ordinary committed delegates and proves captured closed state/original facts before observing the positive original commit. Begin/rollback/reentrant/wrong-frame events, dispatcher replacement, configuration drift, incompatible sibling capsule, wrong primary or expired budget invalidate; observer restoration is ownership-conditional. Tax installation eagerly refuses an already installed V1 or NEW-command observer. Their frozen factories cannot eagerly recognize future Tax types: reverse wrapping must instead be detected by Tax ownership checks on the still-delegated commit path before physical commit, while preserving the replacement dispatcher. There is no symmetric eager-rejection claim or edit to frozen factories. Arbitrary nondelegating dispatcher replacement requires the owner’s terminal fence; this prerequisite must not claim that an observer no longer invoked can intercept a physical commit. Closed proof always refuses replacement and cannot compensate already committed effects. The older private abort marker is an ownership witness in the same original transaction, not a new source frame or renewed authority. Routine younger HeldSourceTransaction RELEASE/SAVEPOINT cycling must leave it intact; normal source proof never releases/recreates the older cleanup marker. Cleanup can release the positively present original marker then roll back the entire original physical transaction, never ROLLBACK TO it and continue.

Tax-specific context wraps the *original* generic CommittedReadContext from HeldSourceTransaction and the Tax birth capture; it does not change V1 fingerprint/enable semantics. Two new literal Tax config keys are proposed: `committed_read_receipts_enabled => false` and `committed_read_receipt_version => production-tax-checkout-committed-read-v2`. These keys never read environment or enable a root transport. Capture/proof cannot adopt replaced app/config/db aliases/instances or custom PDO/statement hooks.

It closes exact original order tuple and singleton request/binding/reviewed family plus global provider session/payment identity selectors and permanent definitions. Historical prefix belongs to the identity-owned receipt. While held, MySQL uses qualified current locking reads, bounded/restored row waits and original effective isolation/uniqueness conditions. ## Required lifecycle refinements from the initial independent review

The original [REVISE BEFORE IMPLEMENTATION note](independent-design-review-initial.md) is retained unchanged. The following contract resolves its six required corrections before code; these are proposed requirements, not implemented/pass claims.

1. Cleanup ownership and marker order are established at literal receipt-enabled birth before callback-capable work, and before the younger generic held marker. The owner retains the source/opaque cleanup handle by reference while inside the transaction, not only as its return value; source/receipt access to that same witness covers a first mint failure before a new receipt is returned. Pure frame proof and repeated raw/source fences never release the older abort marker. Two siblings share one idempotent cleanup witness.
2. Capture the original concrete transaction manager, connection name and level1/root record object identity (plus bounded descendants). Cleanup reads those captured objects directly, independent of expired deadlines, withdrawn policy/config/aliases/instances/primary slots and observer poison. It discards only positively identified original pending/committed records and their descendants; a reopened root record, peer records and replacement dispatcher remain untouched. Never use current depth0 alone to clear all records. This capsule’s refusal cleanup suppresses owned deferred callbacks, including rollback callbacks, rather than invoking application callbacks while discarding records; record removal must not be interrupted or replace the original error. It removes original record ownership from the manager only where identity matches, and never resolves a new manager/PDO. Physical rollback requires the positively present old anchor on the captured admitted native PDO; absent anchor or idle PDO gives no rollback or positive-commit inference.
3. Managed afterCommit callbacks execute before TransactionCommitted. If one throws, original writes may already be durable while no matching positive witness exists. The receipt remains unobserved/fail-closed; cleanup suppresses the prepared result, conditionally releases observer ownership and preserves durable effects or unrelated reopened work. No retry, compensation or false rollback claim. A normal committed-listener throw has the same conservative outcome. This does not repair the adjacent ordinary membership P2.
4. Before EVERY closed MySQL source/identity/schema table read, require the captured primary’s `@@session.autocommit === 1` using a nontable query and exact driver/statement/frame checks. Refuse autocommit0 before any implicit InnoDB read transaction can start; do not restore/change that session, begin a transaction or acquire explicit row locks. Bracket each plain read with those static checks. Closed identity sealing/observing/proving must be wrapped by the Tax check because generic identity/plain/generic context methods do not establish this session condition themselves. Internal metadata locks and general SQL wall-time limits are not excluded by “nonlocking”.
5. Third or incompatible mint is validated before mutating the original observer; preserve its valid sibling receipts and exact optional current-admission capsule. If a later mint failure makes original state unusable, leave a poisoned observer installed so a caught refusal cannot bypass physical admission. An early proveClosed is consumed and poisons the still-active fence until owned abort; never restore the ordinary dispatcher and allow a caught early refusal to commit staged writes. A failed committed proof is consumed; after true closure it may release ownership conditionally. Serialization/JSON/deserialization/clone refusal cannot reset one-use or remove the installed fence. The test must catch rejected third/incompatible/early operations INSIDE the transaction and attempt commit.
6. Siblings match the exact source object, exact original reader object (not merely same PDO), birth context, once-capped deadline and optional capsule identity. Earliest Tax birth is sampled before callbacks. Late true/version changes cannot enable a false birth; later caller deadlines cannot renew the original age/cap. Existing nonreceipt reads work with default false keys, and a positive Tax receipt must work while the generic V1 receipt flag remains false. Reverse V1/NEW wrapping is an owned commit-path refusal, not symmetric eager exclusion. Owned restoration never overwrites the replacement dispatcher.
