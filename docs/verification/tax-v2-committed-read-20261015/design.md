## Contract proposed for independent review

SourceV2 remains the sole authenticated source of exact retained order/request/binding/reviewed-payment and original historical buyer facts. It captures strict original Tax configuration at birth, before decryption or other callback-capable services, beside its existing HeldSourceTransaction. It returns unchanged v2 line bytes. Adding closed-original observation never permits accepting that source outside its held frame or reusing it in a new transaction.

The connection-local observer is Tax-specific and concretely typed to V2. It delegates normal events first, closes the optional current consumer admission, authenticates/seals historical identity, then performs callback-free final captured configuration/permanent/raw source/anchor proof. Only afterward is the original identity-owned positive-commit witness prepared. Matching committed event follows ordinary committed delegates and proves captured closed state/original facts before observing the positive original commit. Begin/rollback/reentrant/wrong-frame events, dispatcher replacement, configuration drift, incompatible sibling capsule, wrong primary or expired budget invalidate; observer restoration is ownership-conditional. It must refuse stacking with V1 or NEW-command observers. Private abort marker is an ownership witness in the same original transaction, not a new source frame or renewed authority.

Tax-specific context wraps the *original* generic CommittedReadContext from HeldSourceTransaction and the Tax birth capture; it does not change V1 fingerprint/enable semantics. Two new literal Tax config keys are proposed: `committed_read_receipts_enabled => false` and `committed_read_receipt_version => production-tax-checkout-committed-read-v2`. These keys never read environment or enable a root transport. Capture/proof cannot adopt replaced app/config/db aliases/instances or custom PDO/statement hooks.

Captured raw source proof is server-minted from authenticated SourceV2 facts; expected arrays alone grant no authority. It closes exact original order tuple and singleton request/binding/reviewed family plus global provider session/payment identity selectors and permanent definitions. Historical prefix belongs to the identity-owned receipt. While held, MySQL uses qualified current locking reads, bounded/restored row waits and original effective isolation/uniqueness conditions. After matching commit, fixed qualified plain reads take no locks/transaction and compare original bytes. Existing TaxCheckoutRawPlans requires a NEW-command frame and must not be repurposed by minting a younger frame for this DB::transaction consumer. No callback-capable service may follow the final raw source/identity/anchor fence.
