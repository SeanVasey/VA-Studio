The additional read-only mechanics proposal made during this review is acceptable within this contract: create the oldest private cleanup marker, then a distinct private terminal marker, then allow generic HeldSourceTransaction to create/cycle its younger marker, all inside the same admitted original physical transaction and before callbacks. Normal mint/source proofs do not release either Tax birth marker. At final committing proof, releasing the terminal marker exactly once establishes original Tax-frame continuity without resolving the generic DB path; SQLite's removal of younger generic savepoints is deliberate terminal consumption, while the oldest cleanup marker remains for refusal abort. No younger frame or renewed authority is minted.

Implementation must enforce an irreversible terminal/poison state around that release, bracket it with captured native/default-statement/frame/budget checks and sanitized failure, then allow only callback-free captured context/identity-witness preparation. No further generic held/source/decryption work follows it. MySQL may retain the younger generic savepoint when the terminal one is released, so object phase guards—not accidental SQLite deletion—must prevent any further SourceV2 held use or remint on both drivers. A failed or repeated terminal release must poison/refuse, never reconstruct the marker. Original abort releases only the positively present oldest marker and rolls back the entire owned frame; an absent marker or unrelated reopened transaction remains untouched. This approves the direction, not uninspected code or a new assertion about generic V1 behavior.

After a positively owned whole physical abort, implementation must also leave the captured framework connection/owned manager bookkeeping consistent for legitimate retry, including a refused nested/reentrant path; framework depth cannot remain a fictitious active frame. Only positively owned original state may be synchronized, and a replacement frame's depth/records must be preserved. This follows the existing cleanup/retry acceptance and is a source-review obligation, not permission to clear mutable/global connection state or emit callbacks during cleanup.
