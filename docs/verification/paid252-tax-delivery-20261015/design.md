## Redemption, request budgets and private bytes

Redemption accepts exact batch/authorization UUID plus token, avoiding a new unauthenticated locator transaction. The caller's batch is only a selector: command inspection independently joins authorization account/batch/origin/hash to authenticated current original graph and rejects wrong producer/owner/order, partial fulfillment, prior attempt, expired admission and exhausted count. Token lifetime is valid-to-start at the server-captured admitted instant before identity work; it does not bound or extend later snapshot/transfer. Use a new Tax request-budget type (same numeric timing semantics), and let PaidTaxDeadline bind its live min-only value without casting a Tax source into V1 authority. Existing timing-only request instant may be reused; it grants no entitlement.

First ordinary60s command authenticates exact target and captures immutable inspection. Snapshot starts after that frame closes, default300s, configured30..1800, always capped by the original live request allowance. New Tax spool adapter uses the existing bounded POSIX lease/reservation/readback/unlink mechanism in a separately named private spool; three1GiB slots,16MiB reserve, per-account holder, exact hash/size and private-root checks. No filesystem I/O in a transaction. Cross-family availability: use the existing nonblocking account-heavy key/owner release during snapshot preparation; generic spool capacity across separately named spools is not a measured host claim. Physical storage/snapshot failure refuses before recording an attempt. Original private PDF is bounded16MiB; purchased sources use bounded chunk copying. Path mutations, links, modes, hash/length drift, capacity/slot/snapshot deadline refusal and cleanup retain original files and never overwrite them.

Second freshly authenticated60s command repeats the same batch/owner/SourceV2/graph/authorization/target inspection and admitted instant. The entire first inspection must match, max_downloads still holds, and a unique immutable attempt is inserted. Native current buyer lock acquired before metadata snapshot serializes same-account commands; unchanged min5s lock waits are restored. No retries/deadline renewal. Capture a second source sibling and original consumer closure for before-first-byte, with all new rows included. A physical commit followed by a throwing afterCommit is an honest spent attempt and refusal: preserve durable work, close prepared descriptor, never infer positive receipt from idle PDO or mint replacement proof.

Construct typed transfer before final closed proof; derive transfer seconds as base30 + ceil(bytes/262144), cap7200, counted from redemption commit and never extending the first-byte observation budget. Transfer uses the admitted unlinked read-only descriptor, one-use original sibling proof, live request ceiling before first byte, per-chunk monotonic transfer bound and finally-close on all outcomes. Callback-capable clock/budget/consumer activity before the first byte must precede the final source/owner raw proof; a callback cannot mutate authority between proof and first byte. Consumer callbacks during later chunks are bounded by transfer clock; this remains the existing start-redemption/current-first-byte contract, not perpetual reauthorization. No stream replay/serialization/cloning. Wrong key/late policy/credential/source withdrawal and spent sibling/budget cannot be renewed.
