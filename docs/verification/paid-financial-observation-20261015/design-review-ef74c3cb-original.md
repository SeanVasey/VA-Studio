# Independent A5 financial-observation design gate

DECISION: REVISE BEFORE IMPLEMENTATION

Reviewed exact clean **`ef74c3cbd4104fbee8449efc36161860ae068b30`**. This is planning feasibility only: no new implementation, tests, provider or execution pass is reviewed or claimed.

The narrow factual prerequisite is coherent and feasible. Actual final SourceV1/V2 APIs expose complete1-based line extraction and original held-frame proof; V1 amounts and buyer-reviewed Tax gross can remain distinct. A new internal value/normalizer adds no reason to alter frozen source/receipt/schema/profile bodies or run new native SQL cases. The legacy refunded-exception release purpose must remain separate from delivered-grant refund/access rules.

Three contract refinements are required before code:

1. **Declare the input trust level.** A caller-supplied GET-shaped array matching original paid identity is normalized unverified input. It does not prove provider retrieval, credential/account scope, authenticity, freshness or current financial state. Expose that immutable provenance explicitly and prevent observed/clear/succeeded labels from implying otherwise. A later durable layer needs authenticated retrieval evidence as well as original-source and final-commit gates; the original paid source alone cannot authenticate a new refund/dispute.
2. **Pin exact money/status/projection semantics.** Specify bounded output/state fields, supported USD/strict integer ranges and overflow-safe sums. Preserve Charge.amount_refunded separately from succeeded and each non-succeeded refund status amount/count; pending/failed/canceled are not settled by this normalizer. Define conservative contradiction/incomplete handling without inferring an atomic GET snapshot or net balance. Keep exact dispute history/status and observed disputed bit separate from active access, rights or availability policy. Tax uses tax.order_total_minor, and repeated order gross is never summed once per line. Source lines do not export an original Charge ID, so bind observed Charges to PaymentIntent.latest_charge within the supplied envelope without inventing an original-Charge comparison.
3. **Make factory admission and reconstruction explicit.** Gate both source factories and normalization with the new literal defaultfalse purpose/pins/local-testing policy; raw-admit standard container/env/repository maps before offsets/resolvers and recheck after callback-capable source proofs before issuing the value. Reject serialization/unserialization reconstruction; expose only bounded nonauthoritative summary. Original prove/extraction calls remain under the caller's held frame and original lifetime. They execute existing authenticated SQL/marker proofs, so the precise boundary is no new SQL/DML/schema/provider/transaction/cleanup authority—not a claim of zero existing source SQL.

Meaningful tests should exercise real synthetic V1/V2 frames and complete multiline/source-withdrawal cases; pure metadata/object/serialization/shape/byte/node/depth and money/list/status controls; proper incomplete/pending/terminal history and wrong account/payment/Charge/currency/mode; canonical ordering and no transport/effect. After implementation, require actual frozen source review and original sealed evidence, then cheap exact-head preflight and expected-SHA merge. This design review authorizes none of those results in advance.

Sean's eligibility/window/partial tax allocation/dispute-access/rights/exclusive rules remain open. No values from this slice authorize refund/provider writes, settlement, grants/download changes, inventory release, rights revocation or live merchant operations. Preserve all original/defaultfalse/SDK/API/profile/shared-P2/host/release boundaries. No reviewer app/test/DB/network/CI or shared edit occurred; only runtime originals were written.
