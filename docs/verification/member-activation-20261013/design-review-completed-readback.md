## Required completed-tail and actual-baseline gates

1. A new explicit completed-tail flag must become true only after **all** committed callbacks, raw checks, one successful frame finish, finish admission, reservation postfinish, authorization postfinish and final inspection admission return. Existing `Inspection::$committed` is set before callbacks start; Reservations state `closed` is set before `memberPostFinish` returns. Neither alone proves the tail succeeded. The completed getter must also require the genuine completion entry, actual inserted transition, correct issuer and unretired capture. Review/confirmation/live capture must never issue this handoff.
2. Export the baseline callback-free, while the genuine capture remains registered and closed, before retirement. It must contain the actual fresh inserted snapshot's complete `history.rows()` and `scope()` plus `MembershipRecords::strings` of the exact stored plan, using the same shape and ordering as `HistoryInspection::state()`. Do not export planned history or a caller-built DTO as committed history. Current `proveInsertedActivation` genuinely captures the inserted graph and scope, compares old+planned rows, and replaces the registered snapshot; subsequent observer/committed raw proofs compare that same actual snapshot and complete ledger sets again.
3. Derive `MemberActivatedOriginal` from that authenticated actual history, and require its exact identities, source document and artifact to match the completion result. Its existing `history.original()`/`MemberActivatedOriginal::from()` path performs bounded pure value validation and hashing; it need not call crypto, a clock, a filesystem, container resolution or a closed Rows proof. Preserve the exact result IDs and hashes; public result contents alone are not source authority.
4. The private source runner may retain copied baseline/native PDO values while retiring the inspection, but must register the returned readback only after its outer configuration, original Budget and idle checks succeed. A failure in retirement or the outer tail must leave no admitted handoff. Do not retain live/closed Rows, an `IdentityCommittedFrame`, inspection, producer proof or a callback in the carrier. Keep the returned opaque carrier limited to the immutable public result; copied registry values do not themselves grant authority.

## Exact private authority, consumption and route binding

The Sources registry must bind the exact owner, Sources instance, fixed Reads consumer, definition/redemption IDs, principal/actor object identities, original Budget, captured native PDO, exact readback/result, actual original and exact retained state. The active workflow registration must still match the same locators/principal/actor/Budget. The separately minted owner's `verify` read permit must bind the **exact readback carrier identity**, not just its result contents.

On every attempted use, read and remove the source registration before validation, and invoke the existing owner permit consumer before accepting any source tuple. The owner consumer already removes its registration before checking the exact tuple/Budget. A source mismatch, expired Budget or failed owner check must not leave either authority reusable. A caller-shaped carrier, copied public result, foreign owner/Sources/Reads/Budget/actor/locator, reused permit or retired workflow must refuse. No public generic mode, skip flag, caller baseline, expected-row setter or carrier factory may populate either registry.

**PDO identity must be used, not merely stored.** Require the retained completion PDO to equal the actual admitted pre-I/O route and final inspection primary. A changed native route cannot adopt the handoff simply because it has equivalent rows. The fixed assembly must pass the same Sources instance into Reads; constructing an unrelated Reads object must confer no owner permit. Workflow retirement must remove all its pending readbacks in addition to existing source/claim entries, on success and all failures.

Retain `MemberActivationReadConfiguration`'s real configuration/capability/environment/provenance gates and all idle-route admission. Its constructor may resolve capabilities; capture idle/configuration before that work and recheck afterwards, as the existing path does. Do not replace those gates with a DTO comparison. Internal file observation may never return bytes/path/download authority to a caller before the mandatory final proof. A constructor or file callback that withdraws owner/history/configuration must lead to final receipt refusal, not acceptance of the earlier completion as refreshed authority.

## Final proof, clocks and concurrency semantics

The completed-only verify path must still perform genuine `MemberRetainedOriginals::observe` and `verify` against the handed-off actual original, then the existing full final `MemberActivationHistoryInspection` with the exact handed-off state and original. That inspection must preserve current owner plus historical owner, complete retained graph/257 scope/plan/audit, all callback phases before all raw closures, ordinary committing delegates before its full current closure, distinct committed proof, one finish, postfinish/configuration/original elapsed admission, exact final-result equality, and terminal-safe original-observation assertion. No filesystem/producer/config/frame getter may follow that terminal closure.

The original confirmation Budget is the same object throughout. Its original 300s workflow cap, every source/frame 60s cap, first materialization physical observation cap, honor/producer bounds and later retained-observation cap remain min-only. The retained observation can further shorten the shared Budget; it cannot replace, extend or restart the earlier physical cap. Do not add current invoice/catalog/honor checks to the historical read lane or recover by inventing another authorization.

The new baseline is deliberately frozen at successful activation completion, earlier than the old first historical inspection. A legitimate later credit event in the same period between completion and final inspection can therefore make the exact state comparison refuse the immediate receipt. That is a bounded conservative outcome: keep the committed activation/credit state, report `committed_activation_receipt_refused`, and allow a later explicitly invoked unchanged `readActivated` to capture current historical state. Do not refresh the private baseline, automatically repeat the writer/read, compensate, release, delete the file or renew a Budget to hide that change. Disclose this narrower baseline window in the addendum.

Public `readActivated` and retained replay `probe` continue their original double-inspection sequence and live-gate exclusion. Only an immediate successful new completion can use this one-use handoff.
