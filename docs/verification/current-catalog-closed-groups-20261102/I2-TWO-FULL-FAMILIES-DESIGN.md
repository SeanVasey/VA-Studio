## One stage accounting contract

Constants: B=16,777,216 bytes, R=131,072 transmitted records, P=8,388,608 payload bytes/record, N=65,536 rows/name, F=4096 framing charge ONCE for entire stage, C=256 bytes/record. Each family has28 fixed required headers. Existing failure payload '[null]' is6 UTF-8 bytes, each invalid header costs C+6=262. Original tags/family/slot/kind/ordinal bookkeeping is covered by existing C reserve; this design does not invent literal network-byte precision beyond the existing charge contract.

Before first prepare, compute and validate from fixed recipes h0=h1=28, failureReserveBytes=h1*262=7336, failureReserveRecords=h1=28. Validate safe integer arithmetic and F+failureReserveBytes+h0*262<=B, h0+h1<=R. Reserve covers ALL second invalid headers, not one marker. First valid stream SQL gate:
  COUNT(*) <= R-h1 (=131044)
  SUM(OCTET_LENGTH(payload)+C)+F+7336 <= B
  SUM(payload IS NULL)=0
  existing MAX(header declared count)<=N
with exact original complete family0 H/R wire and P per-row encoding check. If invalid, transmit ONLY its28 original-position headers with '[null]'; R rows suppressed exactly as old invalid protocol. Its failure result is <=28*262+F and stops stage immediately; do NOT issue family1. The first gate itself still evaluates the full family0 wire; transmission bounds do not claim bounded server pages/work/memory/time.

After first full EOF: capture warning count BEFORE close; decode every header/ordinal/cell/name with existing exact contracts; independently count actual transmitted records r0 and sum(payload bytes+C) t0. Reject malformed/null/nonstring/header/ordinal/count/overflow/duplicate, never truncate. Private aggregate accounting becomes usedBytes=F+t0, usedRecords=r0. Verify usedBytes<=B-7336 and usedRecords<=R-28. First decoded facts stay in local unpublished staging memory only. Close cursor, ensure no companion transaction, restore original buffering and confirm success before proceeding.

Second template retains complete exact family1/window/H/R wire, family1 tag1 and original final invalid-header behavior. Source-owned residual integers leftBytes=B-usedBytes and leftRecords=R-usedRecords are validated in PHP as native nonnegative bounded ints; they must be >=7336 and>=28 BEFORE second prepare. Bind only these fixed private integer positions as PDO::PARAM_INT (no caller values/coercion/string SQL interpolation). Gate is:
  COUNT(*) <= leftRecords
  SUM(OCTET_LENGTH(payload)+C) <= leftBytes
  SUM(payload IS NULL)=0
  existing MAX(header declared count)<=N
No second4096 framing charge. Existing P row encoding retained. On invalid second gate emit ONLY all28 '[null]' headers (7336 charge,28records), guaranteed to fit reserved remaining capacity. Decode refuses whole stage. A first-family exact-limit success therefore cannot strand an unbounded/error-header stream. Empty data is still28 valid headers and must consume its actual payload charge. Gate aggregate predicates must retain empty/null refusal behavior; all expected headers always exist. Count/charge calculations cannot discard names or rows.

Second actual stream is independently accumulated into the SAME private accounting before any row can become externally visible. Aggregate valid usedBytes<=B and usedRecords<=R, P and N per-name remain. A SQL gate refusal marker is not absence. Both results must decode completely, warning0, close/restore, context/bookend validation succeed; only then merge disjoint exact enum-keyed families and return to original group caller/cache. Unknown/missing/foreign family, duplicate key, unexpected first/second descriptor, failure in final merge -> discard whole stage/invalidate. No fallback/reconnect/retry/partial return/cache.

Bound proof includes failure: first success reserves future invalid records/bytes; second success stays inside residual; second invalid uses at most reserve. First invalid ends before second. Thus total transmitted charge including all valid/invalid headers <=B and records<=R in every declared SQL result branch. Receiving checks enforce same independently. Unexpected native error/transport failure has no safe metadata result; fail closed and bounded teardown/watchdog, not an invented bounded-error-packet claim.
