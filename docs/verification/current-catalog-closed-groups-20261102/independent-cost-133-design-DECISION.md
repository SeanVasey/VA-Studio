## Return-contract proof required before implementation approval

A fixed JSON-envelope design is plausible, but currently unspecified and unproved. Required contract:

- Every original family SELECT/predicate/native operand collation, source/schema qualifier, branch/native name comparison, binding order/count and result multiplicity survives. No LOWER/COLLATE/folding/substitution beyond the original query. Different names colliding under the actual dictionary relation still appear in every matching name branch.
- Each envelope carries fixed group/family/name tags and a full ordered cell array or equivalent schema-pinned representation. Reconstruct PHP associative fields in the ORIGINAL projection insertion order, not JSON object key order. Preserve PHP int versus string versus NULL exactly; numeric-looking names/defaults/text must remain strings, NULL definition remains NULL, and empty string differs from both. Do not use permissive PHP casts or numeric-string inference. COUNT and all integer metadata need exact native range/representation proof. JSON number decoding/unsigned values, character conversion, escapes, Unicode and definition text require native differential evidence.
- UNION may combine only identical envelope transport columns with an independently proved lossless encoding; it may not coerce original heterogeneous metadata columns. JSON extraction/serialization itself cannot truncate, round, normalize or change NULL. Independent original-vs-batch native queries must compare strict typed arrays, including key order and complete values; pure expected arrays alone cannot prove server transport semantics.
- Preserve original ordering per family/name, including composite order keys and numeric ordering. SQL aggregation has no implicit input ordering; a JSON_ARRAYAGG/UNION traversal assumption is inadequate. Explain deterministic transport ordinal generation and source-defined tie behavior without sorting away discrepancies in tests. Families without original order need equivalence of multiplicity/consumer semantics, not an invented strict sequence claim.
- Empty family must be distinguishable from a missing/corrupt family transport. Fixed headers/arity/tag grammar must reject duplicate/missing/unknown families, invalid ordinals/types, invalid JSON/UTF8, unexpected columns, truncated/oversized envelopes and decode overflow. No best-effort fallback to an old stale query or dropped row. Finite caps must fail closed, never truncate. Any newly unsupported legitimate large catalog must be identified as a support limitation; do not silently reduce the existing namespace/dependent scope.
- No global proof cache, account proof reuse without physical MDL/witness, changed first/full/terminal semantics or memo14 density reduction. Retain original current context/session checks and aggregate accounting, including any additional transport verification work.

## Profiler assessment

The proposed external profiler is NOT executable as currently drafted. An after-window printed total does not solve exact event boundaries/ownership or history eviction. A small separately reviewed read-only consumer/instrument/history-capacity preflight may be useful later, but is optional for source design and is not permission to poll or run the inspector. Do not enable/reset consumers, capture SQL_TEXT/binds/secrets or scan unrelated actors. If profiling is later necessary, first provide an exact immutable harness with defensible owned-thread/window reconstruction, history completeness, finite cleanup and primary90/companion43 agreement. Marker SQL would change counts unless clearly excluded as diagnostic instrumentation; it cannot become the unchanged acceptance result. A missing PFS trace is inconclusive, not license to infer the desired decomposition.

Proceed with source-only exact group/return-contract preparation, prioritized ahead of interruption-test implementation. Any production decoder/compiler/caller repair needs a coherent exact-source review and bounded native differential proof before rerunning the unchanged aggregate110 gate. Nothing in this decision raises limits, weakens primary authority/guards, removes temporary/current proofs, changes isolation, moves construction outside the window or accepts the member prerequisite.
