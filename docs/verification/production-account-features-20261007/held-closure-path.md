# Exact held-context floor accounting

This change removes three duplicate identity schema inspections from the NEW253 module reader. It does not replace, cache or relax an identity floor, alter the original ten-second deadline, or change migration installation admission.

1. `ProductionFeatureOperation::run` captures the original deadline and standard raw configuration/PDO admission, then installs one connection-local dispatcher decorator and a standard operation-scoped transaction manager. The decorator creates `ProductionFeatureTransaction`'s physical marker before any ordinary TransactionBeginning delegate; other connection/original-manager pending records are untouched and original manager/dispatcher are restored in finally.
2. Only `ProductionFeatureContext::locked` can construct the final context; its constructor is private. The factory calls the byte-exact borrowed `ProductionAccountFeatureAccess::lock`, then proves the outer marker and raw configuration before constructing the module context. Access delegates to `ProductionCustomerAccess::lock/read`, whose `IdentityRows` constructor and terminal `assertPermanent` both call the exact approved `IdentityMigrationOwnership::inspect` seven-table/parent floor.
3. NEW `ProductionFeatureSchema::assertHeld` accepts only that context. `heldStorage` proves the original module savepoint or the same one-use typed committed frame, captured PDO/database/framework depth and deadline. There is no raw PDO overload, optional skip boolean, untyped principal or feature policy switch. Its module proof still checks every NEW target namespace/type/column/index/FK/guard, all original users/accounts dependencies, and the exact retained250/242 legacy floor.
4. After all module/catalog/decrypt/clock/source callbacks AND ordinary TransactionCommitting delegates, the decorator invokes the sole `Context::proveCurrent`, which closes module/configuration/retained-row proofs. It then invokes the byte-exact typed original-binding historical proof (when initialized) and current identity proof. Those routines repeat full permanent identity inspections at entry and terminal; the current proof remains last. The outer physical marker is then checked without a repository/query callback before regular commit.
5. After regular commit/events, raw parent/statement admission precedes creation of `IdentityCommittedFrame` with the original deadline. Typed `lockCommitted` performs the full current identity floor before module validation. `Context::proveCommitted` checks module floor/rows/configuration and the original signed binding in that same frame. Final `FeatureAccess::proveCommitted` again performs the complete current identity floor, fresh mutable authority reads and one-use physical close. Only prebuilt output follows.
6. `ProductionFeatureSchema::up` and public raw `assertComplete` retain the full exact identity dependency floor. Installer admission, global prefix validation, final complete assertion after the last DDL callback, and permanent rollback refusal remain complete. The shared identity helper and all old101 bodies are unchanged.

`ProductionFeatureHeldFloorTest` removes an actual identity guard before entry, during an actual Saved hook, and after regular commit. Entry refuses before writes. Late SQLite DDL is rolled back with the original write; native implicit DDL commits retain the valid original revision and return unknown. Commit-event withdrawal withholds output until the guard is restored, and the original data remains readable by the same current owner after restoration.

`ProductionFeaturePlainConfigurationTest` preserves the original actual two-case ArrayAccess red. The postcommit case disabled the purpose only inside final current identity proof and released the old grant projection. Raw standard repository items/parent arrays and typed primitive leaves now refuse before lookup; custom callback-bearing statements are also rejected. Built-in PHP8.4 `Pdo\\Sqlite`/`Pdo\\Mysql` are admitted exactly alongside basePDO, while subclasses and custom statement classes are refused. No dependency source is modified.

Configuration snapshots recursively detach PHP references. The scalar-reference original released granted/canGrant:true after the live enabled flag becamefalse; purpose/rollout/public snapshots now keep immutable captured primitive values. The environment reader inspects the exact standard Laravel offsetSet-generated scalar closure without invoking it and refuses callback-bearing env resolutions. Per-operation manager/dispatcher and standard PDO/statement admission follow delegate phases; no identity/deadline is renewed. Original framework beginning/committing/afterCommit/committed callbacks keep their order. After original physical commit, additional ordinary delegate transactions must not be intercepted as the original protected frame; their effects are assessed by the same captured one-use committed closure.
