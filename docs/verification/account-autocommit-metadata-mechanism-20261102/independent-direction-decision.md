# Independent fresh metadata PDO architecture direction

Read FRESH-METADATA-PDO-ALTERNATIVE.md at source3238dfb6, actual prior RR/3550/publication STOP assessments, config/database.php and IdentityMetadataAdmission's raw admission contract. Source/evidence only; no DB/container/native/tests/product source changes or agents.

Decision: RECOMMEND A CLOSED SAME-PRINCIPAL AUTOCOMMIT METADATA COMPANION AS THE NEXT FORMAL REPAIR DIRECTION, SUBJECT TO A SMALL EXACT-SOURCE FEASIBILITY PACKET FIRST. Root may explicitly expand the old same-PDO experiment scope; that restriction was a selected diagnostic boundary, not a binding user prohibition. No product implementation/adoption or execution is approved here. Some same-PDO SHOW/compound arms remain untested; do not claim they all failed. The companion is nevertheless a concrete plausible alternative to an observed stale owned-RR catalog and natively rejected I_S locking read.

The minimum architectural split is precise: primary PDO remains sole business/identity/transaction authority; a private operation/frame-scoped raw companion supplies ONLY current permanent catalog facts. Move the existing permanent-catalog namespace/dependent queries, not their semantics or scope, to that capability. Keep primary account/identity MDL, witness/deadline, raw connection admission, session settings, transaction mode, temporary-shadow SHOW/probes/counters and actual rows/authentication on primary. A metadata companion cannot prove session-local temporary state or own uncommitted application changes. It must never issue domain SELECT/DML/DDL/CALL, execute metadata definitions, renew a witness/deadline, reconnect/fail over or become a framework connection.

Fresh-connection-specific P0/P1 prerequisites:

1. **Canonical writer construction without callbacks.** Extend existing raw IdentityMetadataAdmission capture with an explicitly closed scalar writer descriptor. Use the already captured default connection's raw resolved config, exact primary object and native internal PDO class; never invoke config()/env()/getPdo(), URL resolver, connector/factory, read-pool, reconnect closure or user callback inside the boundary. The existing class admits plain raw configuration but does not yet prove a canonical reconstructible DSN. That new validation is real work, not supplied by current admission.
2. **Transport/TLS/config equivalence.** Smallest first supported descriptor: mysql writer, null URL, one scalar host+validated port OR canonical unix socket, exact database/charset/collation/prefix contract, scalar username/password, no persistence/init-command/custom statement class/multi-statements/local-infile/unknown options. Use correct native DSN encoding or reject separators/NULs; never hand-build an injectable DSN. Preserve supported SSL CA/client/verification options exactly rather than silently dropping them. config/database.php actually permits null DB_URL, scalar DB_HOST/PORT, DB_SOCKET, utf8mb4/unicode_ci, timezone+00:00, strict=true and optional SSL_CA; audit those real supported cases first. A nonempty socket with the config's unused default host is not automatically an attack: match Laravel's canonical socket precedence explicitly, not an invented contradictory rule. Unsupported URL/host-list/read-write/custom TLS configurations may refuse only as a documented compatibility limit, not silently be redirected.
3. **Same live identity.** A fixed handshake, before metadata authority, compares selected DATABASE, serverUUID/version, CURRENT_USER and USER/login/roles, supported session attributes and primary captured writer descriptor. Companion autocommit1/no open transaction/native RR must hold before and after consultations. A same-principal observer cannot simply assume the primary was connected to the reconstructed endpoint. Bind both live identities and preserve TLS assurance; UUID is identity evidence within the admitted transport, not a substitute for TLS/authentication. Any mismatch/loss/change invalidates; no silent reconnect.
4. **Closed canonical setup is allowed.** Requiring natural server defaults to equal Laravel's initialized primary is unnecessarily brittle. The existing config deliberately specifies SET NAMES utf8mb4 COLLATE utf8mb4_unicode_ci, timezone+00:00 and Laravel strict mode. Permit an explicitly reviewed fixed initialization sequence on the new companion for those canonical values, then verify effective values against admitted primary/config. This is bounded session initialization, not arbitrary INIT_COMMAND, copying uncontrolled variables or changing primary isolation. Do not interpolate arbitrary config SQL/modes or issue SET ROLE/global settings. Active primary roles differing from new default roles should fail closed unless a separate closed role-initialization contract is reviewed. Error/fetch/native-prepare/select-limit settings must have exact supported values. Record setup costs and never print credentials or credential hashes.
5. **Private lifecycle/cost.** One companion per existing admitted frame/operation, with autocommit catalog statements and fully fetched/closed cursors, is the practical smallest lifecycle; per-boundary reconnect is unnecessary authority and likely expensive. Keep no global/persistent companion registry. Bind it to exact primary/config/server/context and original deadline; at each consultation require unchanged primary witness/token and companion context/no transaction. Close on failure/operation end, never replace it transparently. Historical migration-only code outside a frame needs its own explicitly scoped instance, not use of an arbitrary global provider.
6. **Cross-PDO proof composition.** Pin primary owned tables BEFORE companion permanent metadata proof and recheck primary transaction/session/witness after. Stable version/fingerprint is captured under that MDL. Namespace/dependents not blocked by MDL are freshly rechecked at each existing boundary and full terminal proof as today; companion currentness does not make multi-query inspection atomic. Primary temporary shadow checks remain per existing boundary, including temporary tables named for the alternate trigger namespace. Keep primary @@foreign_key_checks/sql_mode/etc checks on primary; companion values do not prove them.
7. **Aggregate counting cannot be evaded.** Full110 and memo15 include every primary+companion SQL setup/handshake/context/catalog query in each gate's actual window. Existing one-PDO subclass counting is insufficient. Prefer batched fixed context queries and move existing metadata work rather than duplicate it; use aggregate counters/instrumentation, report constructor/handshake wall time and simultaneous sessions too. No passing count is predicted, and budgets cannot be raised. If true aggregate cost fails, redesign or leave blocked.

Inherited obligations versus new blockers:

Global metadata visibility of hidden peer objects, NULL definitions, role changes and exact cross-schema qualification were already activation conditions for existing dictionary-based ownership on main. Same principal does not solve them, but their existence does not uniquely disqualify a companion or require a speculative new privilege model before testing its freshness. Preserve current fail-closed visibility/ownership contract and explicitly report its existing unverified activation conditions. The companion-specific delta is proving equivalent effective principal/roles/transport and no reduction in catalog visibility, not claiming positive objects prove omniscience. No new grants or elevated observer are proposed. Source-level config class/callback/adversary defenses remain necessary new tests around the construction boundary, not broad reasons to avoid selecting any direction.

Likewise any cross-schema dependent scan currently snapshot-sensitive must move to current catalog access within its ORIGINAL scope; do not broaden runtime identity admission into migration-only account foreign floors. Inventory AccountAdmissionGuards full/memo/terminal, IdentityMigrationOwnership inspect/assertNoDependents/migration floor, ConsentMigrationAdmission, SchemaProofFrame callers and unframed/committed/historical readers. Preserve original migration/helper-emitted V1 bytes and runtime row/authentication contracts. This inventory is essential implementation design but need not be implemented inside the first mechanism probe.

Smallest useful next mechanism test (source preparation/review, then separate root lease):

- One new internally random scratch selected+peer schema, minimal anchor/account/foreign objects; no Laravel/full fixtures. Three owned native roles: primary business RR transaction with early anchor1/MDL/savepoint, publisher, and same-canonical-writer raw companion in autocommit. Optional PFS observer is observation only. Configure the same intended canonical initialization; pin same serverUUID/principal/roles/schema identities with redacted credentials.
- Prime the actual frozen prepared namespace primitive and relevant exact metadata queries on the companion BEFORE publication, including negative SHOW cache controls, WITHOUT BEGIN or business-row reads there. Independently publish all six namespace classes, table/view aliases/case/accent/PAD, both routine types, index versus CHECK/UNIQUE/FK, and peer-qualified controls using fixed finite SQL. Fresh publisher metadata supplies exact relation controls; primary still reads anchor1 and keeps savepoint while publisher confirms anchor2. Companion must repeatedly detect newly committed objects via the original exact predicates/app primitive on its autocommit statements and remain outside transaction with cursors closed. Include a second publication epoch on the SAME companion so “fresh constructor once” is not mistaken for reusable currentness.
- Keep primary temp shadow detection as an explicit separate primary control, since companion should not see that session-local object. No app guards are replaced. Capture actual query/warning/identity/transaction/resource and aggregate statement counts for the small mechanism; no110/15 claim yet. Do not monitor publisher DD microsteps under a weakened oracle: retain original first-unexpected-pending STOP contract or separately review a changed diagnostic contract before any source execution.
- Fixed warning provenance controls/ordered stream/finite watchdog/exact owned session cleanup/all objects retained remain. Currentness mismatch/identity loss/implicit transaction/unknown warnings/waits stop; no retry/fallback. Root-only success still labels restricted-principal visibility untested.

This finite test can establish whether reusable autocommit metadata access escapes the exact observed RR primitive defect while preserving the business view. It cannot prove the whole architecture, costs, factory security, actual account isolation or ledger/member acceptance. A positive result enables exact private-capability implementation design/source review and focused actual boundaries; a negative result selects no repair. No DB or product action follows from this memo. Original failures remain retained, mount false and no accepted headroom.
