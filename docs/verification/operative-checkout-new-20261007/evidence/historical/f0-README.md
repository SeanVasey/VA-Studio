# Operative checkout — new work, development candidate

This lane adds actual payable review, affirmative buyer assent, immutable order,
durable provider request, own-account Stripe SDK dispatch and retrieved-payment
reconciliation code. It does not modify the historical test checkout graph or
claim T22 completion. Source is a local development candidate awaiting independent review. No live
credentials, network payments, activation, hosted CI, push or merge occurred.

The supported initial path is an explicitly owner-delegated qualification policy
and buyer/candidate/selection-bound declared exemption; verified-account identity;
unscoped, nonexclusive, exact published v1 USD offers; card payment; one immutable
hosted request and one original confirmed payment. The owner policy retains tax
source commitments and qualification scope/reference/hash. Staff MFA and a
configured qualifier ID alone cannot create the required authority. Synthetic
fixtures explicitly retain rehearsal provenance and certify no actual seller,
qualification, tax position, account or payment fact.

## Default-off composition boundary

Every config activation flag defaults off. No shared root file is edited. Root
alone composes the new provider binding, route file and globally prepended privacy
middleware, plus sanitized exception reporting/response handling for this prefix.
Tests explicitly register the owned components. The global prefix boundary is
needed for unmatched 405, CSRF, session-lock and throttle failures. Errors rendered
inside Laravel's routing pipeline also require root's exception matcher; the
owned middleware alone is not claimed as complete integrated privacy acceptance.

HTTP receives identifiers, the exact reviewed hash, a literal affirmative assent,
and a buyer-declared legal name. It accepts no totals, origin binding, merchant
context or payment status. The new identity session API must validate its original
credential/origin/access marker before returning the typed principal. A cached
customer guard user or historical test principal is insufficient. Browser return
performs a retained status read only, with no provider I/O or financial write.

## Runtime evidence and retention

Funds execution (`test` or `live`) is separate from the existing machine policy's
declared commercial target `live`. Production-capable code supports eventual
configured live own-account execution; injected HTTP/provider fixtures are limited
to local/testing rehearsal and cannot enter that path. No historical test evidence
is relabeled. Current T23 buyer authority is required for fresh commands and buyer
projection. Original durable buyer binding and later recovery history remain
distinct; recovery never relinks an order's original owner or assent.

The request is committed before provider I/O, with frozen exact line, money,
metadata, mode, own-account, expiry and idempotency commitments. The SDK uses its
pinned version, own-account GET without Connect context, bounded transport and no
automatic network retry, outside database transactions. The response to POST is
only a session locator; authoritative GET and separate PaymentIntent GET must
agree on the complete line mapping, total, capture and confirmed received amount.
No redirect, client amount or webhook assertion substitutes for those reads.

The original request is never extended on retry. The configured provider lifetime
must include its retry allowance above Stripe's 30-minute minimum, and the adapter
checks remaining expiry immediately before POST. Unknown outcomes append bounded
uncertainty evidence. A financial observation is retained even if buyer credentials
or current software source withdraw during provider I/O; buyer access is checked
again before projection. First authoritative observation after the original
attempt deadline becomes a retained paid exception, not automatic fulfillment.
Terminal session states cannot regress through intervening uncertainty records.

The ten new immutable tables and guards are installation246000. The migration
resumes only an exact **empty** installation prefix; a complete installation can
retry uncertain repository logging while preserving records. Populated partial
installations, interior gaps, schema/guard drift, temporary shadows, foreign
references and reserved namespace aliases refuse before any migration write.
There is no cleanup, replacement or operational down. Installation requires
stopped writers; this is not a concurrent online-DDL protocol.

The future paid grant consumer has a separate two-step source seam: locate the
original buyer/order commitment without locking order; prelock T23 historical
identity; authenticate the complete original order/line/provider/payment graph
using the consumer's captured primary CurrentRows; mint a nonserializable typed
source; recheck the retained source and original identity prefix before consumer
commit. This source performs no grant write. It excludes paid exceptions and does
not itself confer current buyer access or production grant capability.
