## Next dependency-ready increment

**T12a: fresh persisted operator authority and MFA acceptance, using the existing verified-staff policy.** No new commercial policy or private export is necessary to test this boundary. Do not create a new role hierarchy in this increment.

Concrete hypothesis: `SaveTrackMetadata`, `PublishTrack`, media queue/binding and rights/offer services call `Gate::forUser($actor)` on the supplied object. The gate currently reads that object's `is_admin`/verification fields. A retained or locally modified User may therefore carry obsolete authority. `SiteContent::actor()` already reloads the persisted user specifically to reject that condition, and preview tests cover it. `TrackMetadataTest` tests replacing the request actor and fresh unauthorized objects, but not retaining an authorized object while revoking its database row. This is a source-backed gap, **not a confirmed HTTP exploit or a claim that existing browser access is broken**.

Start in a separate checkout with failing regressions for retained operator objects after persisted role/verification removal or deletion, forged unsaved/locally elevated objects, and restored valid authority. Cover direct metadata create/edit and publish/unpublish without mutations/audits on denial. If confirmed, enforce one fresh persisted gate rule shared by existing catalog/rights/media consumers; preserve existing legitimate console/test callers and exact contributor-review rules. Separately verify `AdminMultiFactor::satisfiedBy()` against persisted removal/required-rule changes: it currently checks enrollment on the supplied object. Enrollment checks do not prove a successful second-factor challenge.

Preserve framework authentication/recovery semantics; no custom TOTP implementation or weaker recovery fallback. The full T12 permissions/bulk/defaults/track-visibility outcome remains open.
