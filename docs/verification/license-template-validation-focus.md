# License-template validation focus recovery

October 6, 2026. Bounded correction to PR #9 source `5bc7cbd` (published `9bea39d`, tree `80f979a`) after the original Chromium journey in Foundation CI run `37480884798` failed at `license-template-authoring.spec.ts:110`.

## Observed failure and source finding

Submitting a nonempty whitespace template name reached the server and returned HTTP 200. The required-name error was visible, the slug and type were retained, and the create dialog remained open and within the viewport. The unchanged focus-containment assertion found focus outside that dialog throughout its ordinary ten-second observation. The retained screenshot and error snapshot show this actual focus loss; later creation/edit/stale-save steps in that journey were not reached. The exact browser-level cause of the initial focus loss is not established.

The existing shared modal attributes repair focus after an opening transition only. The locked Filament schema validation handler expands and scrolls the first error but does not restore keyboard focus. Its schema `validate`/`validateOnly` paths dispatch `form-validation-error` with the component's `livewireId`; template domain/review errors thrown by `throwFormErrors` bypass those methods and previously dispatched no such event. The locked Livewire distribution emits response dispatches from `onMorphed`, after applying the response HTML. The passing metadata-preset comparator also lacks explicit name autofocus, so no field-autofocus difference is claimed as a cause.

## Bounded behavior

Only template create/edit modals receive a recovery handler, while retaining the existing opening-transition behavior. It listens to the existing scoped Filament event, waits for Alpine's next tick, and requires the same connected, open, visible, topmost modal with an actual validation error. If focus is already inside that modal, it leaves it in place. Otherwise it focuses the first error's enabled input (excluding hidden inputs), select or textarea, with the modal itself as a fallback if the control cannot receive focus. It does not change values, submit, retry, recapture a review, or make a write.

The existing domain-error helper emits the same component-scoped event before throwing its mapped validation error. Ordinary schema validation keeps Filament's original dispatch. Existing create correction, consumed edit review, current authority/MFA, frozen identity and stale-edit rules remain intact. Shared modal helpers, vendor files, browser tests, test timeouts and assertions are unchanged.
