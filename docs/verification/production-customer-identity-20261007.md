## Retention, admission and recovery

Migration `2026_10_07_247000_production_customer_identity.php` owns seven new tables and 21 named SQL guards:

- Addresses serialize rate admission and completion on the normalized address HMAC.
- Challenges retain provenance, policy, private encrypted payload commitment, proof HMAC, bounded lifetime, availability and any original recovery binding.
- Origins retain the first mailbox-controlled account association and owner commitment.
- Verifications append a signed, chained observation for enrollment or recovery, with exact completion replay commitment.
- Notices retain the immutable challenge/template association.
- Attempts retain a one-use claim token HMAC, attempt number and lease.
- Outcomes retain accepted, definitely-not-submitted, unknown or blocked facts.

All seven tables are append-only under SQL guards, including conflict/replacement admission. Unique/FK identities and v4 UUID/hash/type/semantic shapes are checked. Enrollment refuses existing users, test accounts, staff or matching legacy identities; eligible new accounts are created only from a returned proof. Recovery retains the same owner and freezes original user/account/origin/access/credential context. Unsupported provenance/policy, authority withdrawal, conflicting completion replay, stale recovery credential, invalid proof, expiry and outer transactions fail closed. Request responses do not disclose eligibility. The fixed technical v1 bounds are ten-minute proofs, four retained requests/address/hour, 128 observations/origin, three worker attempts and a 120-second lease. Public route IP throttles further limit requests; host rate/proxy policy remains a deployment fact.

Runtime `IdentityRows` checks the complete owned permanent schema and guards at entry/terminal, target table metadata before every raw read/write, current primary object/driver/database, and outer/secondary transaction state. It rejects SQLite temporary aliases and explicitly checks MySQL `SHOW CREATE TABLE` because database-qualified names can still resolve to MySQL temporary tables. Current, standalone postcommit mint, historical, caller-owned reader, request, completion, session, worker and scanner paths all use this context. Foreign PDO readers and incomplete/aliased physical floors are rejected.

The notification worker resolves transport and decrypts private content before terminal primary proof. Direct terminal reads close actual address/user/account/origin/challenge/notice/attempt/outcome state, bound claim token, lifetime and feature/capability settings after transaction-commit callbacks. No framework query event, model, container, crypto or renderer callback lies between that final proof and transport invocation. Terminal clock capture precedes proof; pure monotonic elapsed time conservatively accounts for subsequent metadata latency without a Date/container callback after the proof. A positive SMTP 250 records submission acceptance only; it creates no verification observation and asserts no delivery.

`DefinitelyNotSubmitted` permits a retry only when the transport positively knows that no message DATA bytes were sent. Retry delays are 30 and 60 seconds and a third attempt is final. Starting a DATA write makes later refusal, partial write, disconnect or lost acknowledgement ambiguous. Such outcomes and expired unresolved leases are retained as unknown and never automatically resent. An acknowledgement observed after lease expiry is retained as unknown, preserving the submission uncertainty. Jobs contain only a numeric notice selector, use one queue attempt and operate after commit; queue wake-up failure leaves retained work for `customers:process-identity-notices --limit=50` (valid range 1–100). The scanner skips completed or expired unattempted challenges so they cannot starve later work, while still sealing outstanding expired claims.

The direct PDO migration admission checks the full installation before any DDL: exact tables/columns/indexes/FKs/guard bodies and object kind/case, dictionary aliases, temporary shadows even without a physical owned table, unsupported engine/options and foreign references. An empty exact contiguous prefix of tables then guards can resume; later objects after a missing predecessor, unexpected metadata, foreign trigger/view/routine/FK dependencies, or populated partial installation are refused. Complete populated history accepts `up()` without modification. `down()` refuses any retained identity/outbox rows. Empty rollback reverses guards and tables and can itself resume at an exact empty prefix. Stop application writers and other migrators during MySQL's implicit-commit DDL; this is not an online DDL claim.
