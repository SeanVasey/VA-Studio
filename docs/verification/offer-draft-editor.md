# Captured offer draft editor

The existing offer editor previously submitted a full draft without retaining the operator's baseline. An older tab could therefore restore fields saved by a newer tab. The edit action now captures the current draft through [the reviewed domain command](reviewed-offer-draft.md). A conflicting or consumed review requires closing and reopening the editor; it does not silently recapture a different draft.

The action preserves the current create, publication, deactivation and immutable-history behavior. Only the existing draft license, integer price, currency and exact deliverable selection are submitted. Its existing published-license, positive-price, USD and ready same-track asset choices remain in force. Saving does not publish a revision or change purchased terms.

## Real action lifecycle

`ManageOffers` retains locked server review/context properties. A real edit mount captures actor, record and table/action context. Direct callback invocation, substituted records, changed arguments, unknown fields, track changes and table/pagination changes cannot reuse that review. Ordinary changes to the four form fields preserve it. The submitted review is consumed before action visibility and form validation, so validation failures and repeated clicks require reopening. Fresh authority and required MFA remain server checks.

The edit action disables Filament's surrounding transaction so the domain command retains its standalone actor → track → offer locking contract. Filament's custom processing callback updates only through that command. Its disabled track relationship cannot save a substituted track, and no later framework model save can overwrite the result. Approval and publication actions remain separate.

Validation maps captured-review errors to the visible price field and preserves entered values. The existing approved modal reflow/focus behavior brings errors into view. Unexpected errors use a fixed private log with only the exception class and say that the result could not be confirmed. They do not claim a rollback or successful save. Reopening reads the actual durable draft. Consumption is a current component-state guarantee; it is not a durable single-use token protocol against literal replay of an unchanged old signed snapshot. Persisted row and participating audit identities provide the domain conflict fence.
