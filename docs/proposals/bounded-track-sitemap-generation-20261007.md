## Decision and source contract

Retain a complete partition of published candidate identities at one database epoch. Retain no eligibility assertion or canonical track paths. A track that is ineligible during generation still belongs to its private candidate window; therefore a license-start/hold-expiry or restored private byte can make it appear on its next freshly checked page without a new identity generation. A database graph mutation invalidates the entire generation, because10d's17-table epoch guards cover current eligibility and published candidate identity. Config/canonical-origin identity changes also fail closed until a new generation completes.

`CurrentEligibleTrackSnapshot::currentPaths` must continue to carry its authenticated original deadline as a maximum. Never decode an old EligibleTrackSnapshot and mint a renewed eligibility token from it. A new, separately typed/purpose-bound CandidateWindow represents only identity partition membership and has no eligibility deadline/paths. A fresh eligibility decision from those identities is a new decision, not extension of the old one. The constructor/minting path is internal and the consumer verifies the purpose, generation association, epoch, ascending positive IDs (at most48), configuration identity and owned store.

Current source anchors: CurrentEligibleTrackSnapshot::captureCurrent rejects caller depth, captures primary PDO, sets next MySQL transaction READ COMMITTED, checks actual readiness/inventory at explicit time, bounds license/held deadlines and proves ownership/identity/epoch/config/deadline through final captured PDO. DiscoveryEpoch verifies singleton,54 guards and17 native InnoDB dependencies; epoch fence is last. The existing public index only advertises the bounded editorial child; PublicPagesSitemap validates canonical origin and escapes loc values. routes/public-discovery.php has session-free throttled discovery and strict request-body/query refusal. These contracts must be preserved.

## Bound and private-count protection

Proposed application cap:128 fixed public track slots,48 private candidates per slot, hence6144 published candidates maximum for this first child. Every step scans at most49/takes48 candidates; the cap is explicit capacity, not an assertion about production catalog size. The129-entry combined index (128 fixed track slots plus the existing editorial child) stays fixed whenever a complete valid track generation is advertised. Always advertise all128 slots, including empty slots. Do not publish the private used-window count, candidate count, skipped IDs, draft count, generation chain hashes, epoch, cursor, ownership seal or source commit. An empty/all-ineligible complete generation exposes the same slot topology as a nonempty one; each page can contain an empty urlset.

Public paths include only a random public generation identifier plus a fixed slot number; it is not a source hash, ownership secret or authorization token. Old generation URLs refuse after epoch/config change, even if a successor is complete. An invalid/incomplete generation contributes no track slots to the existing index; the existing editorial child remains independent. All out-of-range/unknown/private-generation/body/query requests have a uniform response; do not use response messages to expose internal counters.

At128 full windows, one bounded49-row scan proves whether another candidate exists. If there is overflow, refuse completion/publication of track slots; do not truncate and label complete. No public handler scans/rebuilds/counts the catalog or requests more than one private candidate window. Selected upper bounds: index512KiB, individual child128KiB, loc length less than2048 characters, UTF-8/entity escaping, canonical same-origin absolute locs. Protocol ceilings are50000 entries and52428800 uncompressed bytes for each sitemap and index; this application cap is deliberately below those ceilings. Primary protocol: https://www.sitemaps.org/protocol.html (retrieved2026-10-07, index/sitemap limits and same-site rule). Do not emit lastmod/changefreq/priority without actual semantics.

## Store, ownership and bounded completeness

Three additive private tables: track_sitemap_generations (immutable generation identity/epoch/config/start descriptor plus guarded progress/state and authenticated head), track_sitemap_windows (immutable per-generation ordinal, encrypted identity-only payload, prior/head digest, cursor endpoints and seal), track_sitemap_current (owned singleton selected completed generation). Public-generation ID is random; private producer handle is a separate authenticated capability, never logged or returned publicly.

Exact schema/index/check/trigger installation ownership is verified before adoption/read/append. Collision or foreign partial installation refuses before DDL. Native tables must be InnoDB; SQLite connection-local shadows and native temporary shadows refuse. Ownership guards refuse DELETE/REPLACE/reset, identity edits, window overwrite/duplicate ordinal, discontinuous cursor/head transitions and invalid completion/pointer shape; service additionally verifies cryptographic seals rather than treating raw SQL status/count as proof. Guards do not add these bookkeeping tables to catalog epoch invalidation: they are not source eligibility dependencies. Missing/modified guards or damaged seal fails closed; no automatic repair/delete/adoption.

A new run starts at cursor0. Each step verifies its private handle, reads bounded current published identities, then appends exactly one sealed contiguous window and advances the signed head by compare-and-swap. Start/end descriptors cover epoch/config, ordinal, after ID, prior/head digest and fixed capacity. An empty terminal scan seals completion; a final nonempty window with no successor seals its terminal marker in the same owned append transaction. All-ineligible windows still advance. Completion certifies a complete epoch-bound candidate partition, never that every candidate is eligible now.

Retries read at most header+last/requested window through indexed keys. A repeated valid step is idempotent when its exact sealed input/head already committed; a conflicting step/foreign owner/changed cursor refuses, never overwrites or appends a gap. Interrupted runs retain committed windows and resume only under unchanged epoch/config/owned metadata. An epoch/config change marks the run unusable; a fresh run restarts cursor0. No resumption across changed epoch and no silent partial prefix publication. Fixed128 bound makes terminal validation bounded; normal append proves continuity inductively and sealing may verify at most128 records, in the command only. Public index verifies one authenticated completed header/pointer and owned immutable store, without COUNT, graph hydration or chain-wide scans. A child reads only its indexed window; slots beyond private used windows emit empty XML under the same valid completed header.

`down()` unconditionally throws before database reads/DDL, including an empty installation. This preserves data/guards and Laravel migration bookkeeping and keeps ordinary forward migrate usable. No teardown/cleanup/compaction endpoint in this batch; future retention policy cannot delete currently referenced generations or remove ownership evidence by ordinary rollback.

## Transactions and clock/media proof

10d discovery methods require zero caller depth. Do not nest them under a locked generation transaction. Structural window capture is standalone. Append/publication is a second owned transaction: capture fixed PDO/depth, lock generation/pointer bookkeeping first, validate sealed structural input/head and modify own rows, then verify ownership/config/current epoch and take epoch fence last. A race between structural capture and append is rejected by epoch equality; no database/eligibility row locks precede the bookkeeping lock. Domain writers never acquire generation rows; the reader introduces no actor/track/scope cycle. Competing producers serialize on the same generation head; competing pointer publishers serialize on its singleton. These orderings require actual native lock witnesses, not only SQLite results.

Fresh public consumption reads the bounded completed descriptor/window and then runs one zero-depth owned READ COMMITTED eligibility transaction. It verifies generation/ownership and config, reads candidates/current shared license/media/rights/inventory, serializes canonical XML before the final captured-PDO fence, proves epoch/config/connection/depth and current time less than the minimum10-second/license/hold deadline, and commits. Final record fencing remains last. A later DB writer invalidates the generation and every old child route; no cached/304/XML-on-error fallback preserves old paths. Private-media revalidation retains10d's inherited non-sliding60-second integrity cache/safe path checks; this child cannot claim atomic filesystem snapshots or strengthen that evidence without separate engineering.

A long generation can take minutes/days at one epoch: retained candidate identity stays structurally valid, but earlier eligibility windows are discarded. Clock-only eligibility changes do not invalidate the identity partition; every HTTP page takes a NEW bounded decision and fresh max10-second/boundary deadline. An EligibleTrackSnapshot consumption always preserves its ORIGINAL deadline. A license/hold boundary crossing during XML construction refuses. Config/clock inputs must be the same explicit clock/config checked by final proof; do not use independent wall-clock consumers or declare whole-generation eligibility at one time. Different pages can validly reflect different current clocks; the index asserts structural completeness only, not one atomic eligibility instant.
