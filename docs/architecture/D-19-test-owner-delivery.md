# D-19 — Internal owner-bound test delivery foundation

Status: **Approved implementation direction; dependent internal candidate, 2026-09-26.** This formalizes approved proposal `bab4133` and its internal-prerequisite scope against domain source through `47c644c`, schema through `a8d9d1a` and private-stream adapter through `f16a497`. D-17 issuance and D-18 whole-order activation still require their prerequisite acceptance. Final integrated runtime checks and independent review remain gates. No customer download endpoint, UI or production access is implemented by this increment.

Add a separate disabled-by-default local/testing access policy over a fully verified retained activation. Require the configured own Stripe test account and the original order owner key. A grant UUID and a fixed role select the exact first contract or pending-entitlement member; arbitrary paths, current catalog fields and email-based ownership are not accepted. Preserve all purchase, grant, original, activation, pending-entitlement, outbox and exclusive inventory evidence unchanged.

The fixed `test-owner-delivery-v1` policy uses a 32-byte random secret, stores only its SHA-256 digest, expires each authorization after exactly 60 seconds and permits at most one committed stream attempt. A serialized rolling budget admits at most three new authorizations per order in the preceding 60 seconds across all targets. These are technical test limits, not a license's distribution allowance, a lifetime download entitlement or production policy. Never derive them from `copies_downloads` or other licensed exploitation terms.

Require an explicitly provisioned blocked order control before enabling access. Every actual enable/block transition increments its version and is audited under an expected-version check. Missing controls deny. Both issuance and redemption require the current access policy and enabled captured control version. Blocking remains available within the same local/testing account after the access flag is withdrawn. Re-enabling never revives older authorizations; blocking cannot recall bytes from a stream whose redemption already committed.

Persist immutable authorization and redemption records with encrypted canonical evidence. Bind the original owner, complete activation hash, exact target, frozen MIME/ASCII filename, control version and UTC-second times. SQL guards enforce restrictive parent/target bindings, exact policy/TTL, append-only records and one redemption per authorization. Domain verification reconstructs the entire retained graph. Populated rollback refuses before any table or guard is removed, including when only a control exists.

Freshly verify the selected target and prepare a private snapshot outside every open transaction on both issuance and redemption. The issuance snapshot is closed before recording the authorization; redemption retains its newly verified descriptor. Recheck ownership, policy/account, complete database graph, control/version, rolling budget or expiry under the shared order → control → authorization lock order. Recheck time and policy after auditing before returning from the transaction. No purchased-file, renderer, scanner or provider I/O occurs under database locks.

The local POSIX adapter uses three fixed, exclusively locked spool slots per private root. Each holds at most 1 GiB, with a 16 MiB PDF ceiling, a cooperative 60-second preparation deadline and a required free-space reserve of the selected size plus 16 MiB. Verify copied bytes, seal mode `0400`, open a matching read-only descriptor, then unlink the snapshot before returning it. Retain the slot lease until the descriptor closes. Stream media in bounded chunks; never reopen the purchased path after the authorization decision. Crash residue occupies its fixed slot and is never automatically deleted or reused.

Commit redemption before exposing the prepared descriptor. A pre-commit failure closes the snapshot and leaves no redemption; a disconnect or crash after commit consumes the attempt even if the recipient receives no bytes. This provides at most one committed stream attempt, not exactly-once receipt. A caller can request a new authorization under the rolling technical budget. Identical idempotency replay reports `already_issued` without revealing a secret or creating a new authorization; a lost secret cannot be recovered from its digest.

This foundation exposes internal services and an audited control command only. The proposed item reader, owner HTTP/CSRF/privacy boundary, attachment response, frontend controls and browser verification remain a separate dependent increment. Existing customer status continues to show issued contracts awaiting delivery; activation alone is not download access. U-07 guest claims/account recovery, production storage/isolation, object-store or resumable delivery, refunds/disputes, customer library and complete parity remain open.
