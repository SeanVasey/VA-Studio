# Preview queue, section loop and playback controls

This increment implements the queue controls in FP-020 and the section-loop/speed controls in FP-021 for Sean's public tagged-preview player, with optional browser Media Session integration. The existing single native audio element remains the playback owner. These are listener controls; they do not publish content or change licenses, prices, downloads or private-media access.

## Listener behavior

- No audio is allocated or played on first page load. Selecting a playable track establishes the session queue from the current visible catalog. Tracks without a safe preview URL are excluded. Selecting a track outside the retained queue adds it.
- The queue and current playback survive client navigation. A new catalog page updates the tracks available for a future selection without replacing the queue or changing the playing source. Queue state lasts for the current page session; a full reload clears it.
- The queue provides previous/next, move earlier/later and removal controls. Removing the current track leaves its preview playing; automatic advancement then stops because that track has no remaining queue position. Manual Next selects the first remaining item. Pause/resume does not re-add a removed item.
- **Play next automatically** starts off. Enabling it affects what happens when the current preview ends; it does not start audio immediately. At the last queued item playback stops unless queue repeat was selected.
- Repeat starts **Off**. **This track** restarts the current preview when it ends. **Queue** enables automatic next and wraps to the first queued item. Disabling automatic next also turns queue repeat off. These selections do not resume paused or ended audio.
- **Set A here** records the native preview position and clears an earlier end marker. Seek forward and use **Set B here** to activate the section loop. B must be at least 0.1 seconds after A and within the loaded preview duration. Both bounds are visible; reversed/equal bounds produce an accessible explanation. Marking positions while paused never starts playback.
- An active section loop takes precedence over repeat and automatic next. Seeking outside its bounds returns to the section. **Clear loop** restores unrestricted seeking and moves keyboard focus to **Set A here** before the clear action becomes disabled. Changing track or preview revision clears both markers, and a changed duration invalidates out-of-range markers.
- **Playback speed** starts at 1×, offers 0.5×–2× in 0.25 increments, and has a **Reset speed** action. Changes apply to the existing audio element without resuming paused playback. Speed carries between previews during the session and resets on player close. Both native playback-rate properties are updated so a resource reload retains the selected speed. **Reset speed** moves focus to the enabled speed selector before its reset button becomes disabled.
- Native pitch preservation is requested where supported. The panel explains that browser results vary or that pitch preservation could not be enabled. No separate pitch shifting, musical-key transposition, time-stretch library or sample-accurate processing is included.
- Supported OS/browser media controls invoke the same play, pause, previous, next and seek paths. They follow queue boundaries and section-loop bounds. Metadata contains only the public track title, artist and approved artwork URL; audio URLs and commerce records are excluded. A selection is required before controls or metadata are registered. Closing the player clears registered handlers, metadata and position state, and invalidates already captured callbacks.
- The queue panel uses labeled native controls, visible focus, 44 px action targets and an Escape shortcut that restores focus to its opener. Volume and mute remain available in the panel on small screens. Closing the player clears its queue, repeat, automatic-next, loop and speed state.

## Timing and failures

Loop checks use animation frames while the native element is unpaused, backed by native time updates, completed seeks and the ended event. A seek can leave the application in its loading state while native playback advances; that state does not disable an active section loop. Checks wait for an in-progress native seek to finish before seeking back to A. Paused and ended elements remain inactive. This is a preview audition control, not a sample-accurate audio editor: browsers can throttle background execution. Physical iOS/Android and background playback acceptance remain release tasks.

A browser that refuses a continuation play request displays the existing recoverable playback error. It does not skip through subsequent queue items or repeatedly attempt playback. Failed/removed public media remains unavailable under the existing server boundary; the client does not request private masters or stems.

Media Session is optional and feature detection is per capability: an unsupported handler, metadata or position API cannot break in-page playback. Position reports require a finite positive duration and playback rate, and clamp the position within the loaded duration. Physical lock-screen, headset and background behavior still require device acceptance. API contracts follow the [Media Session specification](https://www.w3.org/TR/mediasession/) and the [HTML media playback-rate/pitch definitions](https://html.spec.whatwg.org/multipage/media.html#dom-media-preservespitch).
