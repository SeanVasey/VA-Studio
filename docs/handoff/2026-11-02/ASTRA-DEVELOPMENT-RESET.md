The next selection is the real typed differential method named below. The limited recipe replaces direct reads and domain DDL with observed copies and leaves eight mandatory unknowns; it is not a prerequisite or account acceptance.
4. **Batch sensitive product work.** Focused meaningful tests, one independent review of the actual tested candidate, cheap preflight and required repository gates. Re-review a substantive correction or integration risk, not every documentation commit. Preserve old failures and distinguish old-source carry from new execution.
5. **Keep useful source work moving while tests/reviews wait.** Two or three bounded source tasks are enough. No parallel PHP/MySQL/browser load while ROOT measures or tests. A blocked external review is a lane dependency, not a reason to stop unrelated preparation.

This removes ceremony, not guards: no weakened tests, audit settings, privacy controls, immutable-source protections, native requirements or required security/merge checks.

## How the coordinator keeps work moving

- One task has one named owner, owned files/worktree, acceptance condition and current status: **running**, **ready**, **blocked**, **interrupted** or **done**. Check actual agent state before waiting. Use `followup_task` for an interrupted/completed owner; `send_message` only informs an already running owner. Never wait on an unstarted task.
- ROOT alone registers, polls and closes runtime work. A new candidate fixture may have fresh identity and private datadir; no reuse or signaling of another session's server. SQLite never proves MySQL concurrency. No simultaneous heavy selection during timing work.
- Reserve disk headroom before source preparation: start isolated branches as sparse worktrees, keep only required public paths, and do not materialize another vendor tree while the native fixture needs capacity. - A wait must name the actual external dependency and the next action. During it, assign a disjoint source/test implementation task. If no useful task exists, say so rather than manufacturing another review.
- Keep one concise current board and append a result at a meaningful checkpoint: source SHA, selected command, actual outcome, remaining gate, next owner. Original evidence remains where it is. Do not duplicate hundreds of pins or create a new plan/provenance document for a parameter-only fixture change.
- Freeze meaningful product batches. New P0/P1 blocks; ordinary P2/P3 follow Sean's recorded freeze-and-batch rule unless a specific activation gate names them. A substantive source correction needs its relevant regression and review, not an automatic full-suite replay.
