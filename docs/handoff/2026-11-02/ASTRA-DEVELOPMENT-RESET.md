## How the coordinator keeps work moving

- One task has one named owner, owned files/worktree, acceptance condition and current status: **running**, **ready**, **blocked**, **interrupted** or **done**. Check actual agent state before waiting. Use `followup_task` for an interrupted/completed owner; `send_message` only informs an already running owner. Never wait on an unstarted task.
- ROOT alone registers, polls and closes runtime work. A new candidate fixture may have fresh identity and private datadir; no reuse or signaling of another session's server. SQLite never proves MySQL concurrency. No simultaneous heavy selection during timing work.
- Reserve actual backing-store headroom: use sparse worktrees and avoid another vendor copy. Docker uses **VFS**, so budget the full image clone plus initialization before each admitted fixture; writable-layer size is misleading. Sparse public checkouts recovered about 1.12 GB while preserving owned bytes, but those transient host measurements did not prove mounted capacity. Large lower-layer caches may reclaim nothing when removed. Deduplicate only byte-identical immutable public package files, keep generated Composer/autoload metadata independent, and preserve private/runtime/evidence data. The 3 GiB floor stays unchanged.
- A wait must name the actual external dependency and the next action. During it, assign a disjoint source/test implementation task. If no useful task exists, say so rather than manufacturing another review.
- Keep one concise current board and append a result at a meaningful checkpoint: source SHA, selected command, actual outcome, remaining gate, next owner. Original evidence remains where it is. Do not duplicate hundreds of pins or create a new plan/provenance document for a parameter-only fixture change.
- Freeze meaningful product batches. New P0/P1 blocks; ordinary P2/P3 follow Sean's recorded freeze-and-batch rule unless a specific activation gate names them. A substantive source correction needs its relevant regression and review, not an automatic full-suite replay.
- ROOT owns shared mount files and census integration. Keep the first 150 SQLite-skip entries pinned and append-only; union main's entries first, regenerate selection/counts when touched. Changes adding environment keys require the full `tests/ops` unittest selection. No routine hosted matrices.
- Check the actual final candidate against the existing repository protections. This reset does not change required checks or authorize a security-review bypass. The reset is published through PR #189; later factual receipts ride coherent development batches.
